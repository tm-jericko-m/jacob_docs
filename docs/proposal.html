Background and Motivation

Daily checkins are an important part of Thinking Machines' accountability and transparency practices. They help TM8s record completed work, make progress visible, and support internal reporting. However, recent weekly report data over the past eight weeks suggests that checkin submission remains inconsistent.

Edward currently helps reduce this friction by generating checkins from Google Calendar events. This is useful because Calendar already contains time-based work blocks, but Calendar alone may not fully capture the work TM8s complete during the day. Async coordination, Slack-based updates, documentation, debugging, research, and other unscheduled work may not always appear as calendar events.

This project explores an AI-assisted iteration of Edward that can generate more grounded and useful checkin drafts from available work activity data. The goal is to reduce the effort required to reconstruct daily work while preserving auditability, user control, and conservative handling of uncertainty.

The primary customers are TM8s who submit daily checkins. Secondary customers include managers and operations stakeholders who rely on checkin completion for visibility, accountability, and reporting.

What is the setting and history behind this project?
This project builds on the existing Edward web application. Edward allows TM8s to generate checkins in one click using events listed in their Google Calendar. It was created to reduce the burden of manually reconstructing daily work and to support the company's checkin practice.
Edward has already been helpful, but its current data source is limited. Since work activity can happen across Calendar, Slack, Gmail, tasks, and user notes, an AI-assisted version can improve the quality and completeness of generated checkins.
What is the problem to be addressed?
The problem is the low turnaround rate of TM8 daily checkins. On top of client work, internal responsibilities, and daily deliverables, submitting a checkin may be overlooked. When checkins pile up, it becomes harder for TM8s to remember what they completed during previous shifts.
The problem is not only that users forget to submit checkins. It is also that the evidence needed to write a good checkin is scattered across tools. This makes daily reporting more manual and more error-prone than it needs to be.
What are some current approaches to this problem?
The current approach is to use Edward, which generates checkins from Google Calendar events. This is already useful because it gives TM8s a fast starting point based on scheduled work blocks.
However, Calendar alone may not capture all meaningful work. It may miss async Slack updates, coordination work, task progress, research, debugging, documentation, and other work that was not represented as a calendar event.
Why is this problem worth solving or worth solving better?
Checkins support transparency, accountability, and internal visibility into completed work. Improving the checkin process can reduce friction for TM8s and increase the likelihood that daily work is reported on time.
A better checkin generation flow can also reduce the cognitive burden of reconstructing past work. This is especially useful when a TM8 has a busy day, context switches across tools, or submits checkins after the workday has ended.
How will this product be better than previous approaches?
This project will extend Edward by adding AI-assisted checkin generation. Instead of relying only on calendar event titles, the system can use structured activity data and AI prompting to produce clearer, more complete, and more professional checkin drafts.
The product will start from Edward's existing calendar-based behavior and explore additional data sources such as Slack messages, Gmail context, task notes, or manually provided activity data where feasible. The AI model will help summarize, deduplicate, and format the final output while following guardrails that prevent invented or inflated work.

Goal

What is the goal of this project?
The goal of this project is to evolve Edward into an AI-assisted checkin generator that can produce grounded, editable daily checkin drafts from available work activity data.
The product should reduce the effort required to submit daily checkins, improve consistency of checkin outputs, and support higher checkin turnaround rates.
What are the defining features and benefits of this product?
  • AI-assisted checkin drafting from available work activity data.
  • Faster checkin generation with reduced manual reconstruction of daily work.
  • Improved consistency and formatting of daily checkin outputs.
  • Clear distinction between confirmed work and unclear work that needs clarification.
  • Potential support for multiple data sources beyond Calendar, such as Slack, Gmail, tasks, or user notes.

Important simplifying assumptions:

  • Users remain responsible for reviewing generated checkins before submission.
  • AI-generated outputs should be treated as drafts, not final truth.
  • The system should avoid inventing work or inflating hours.
  • Calendar remains the most reliable source for timed work blocks.
  • Slack, Gmail, and other sources are primarily used for context unless reliable durations are provided.
  • Initial testing may use tunneling or local development before proper deployment.

Deliverables

  • An iteration of the Edward web application
  • An AI-assisted checkin generation workflow
  • A Custom GPT configuration for generating checkins
  • Supporting knowledge files such as prompt instructions, checkin examples, project tag mappings, and non-work event rules
  • A simple validator for generated checkin output syntax
  • An exploratory backend/API prototype for retrieving activity data, if feasible within scope
  • Documentation for setup, testing, and future improvements

Risks and Rewards

What are the main risks of this project?
  1. The AI model may misinterpret activity context from Slack messages, Gmail emails, calendar events, or user notes. This could result in checkins that are incomplete, misleading, duplicated, or too vague.
  2. The system may hallucinate or overstate work. Since checkins are tied to accountability, the product must avoid inventing work, inflating hours, or presenting uncertain activity as confirmed.
  3. There may be privacy and access risks if the system retrieves data from Slack, Gmail, Calendar, or other internal tools. The project should avoid storing raw sensitive data unless necessary and should prioritize least-privilege access.
  4. User trust may be affected if generated outputs require too many corrections. The product must be conservative, transparent, and easy to review.
What are the main rewards if this project succeeds?
If successful, the project can make daily checkins easier and faster for TM8s. It can reduce the manual effort of reconstructing daily work and help users submit checkins more consistently.
The project may also improve checkin quality by producing clearer, more complete, and better-formatted drafts. Over time, this could help increase checkin turnaround rates and strengthen internal transparency and accountability.
