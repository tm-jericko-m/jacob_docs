UC-01: Generate Checkins Using Standard Edward

Summary: A TM8 user generates a daily checkin using Edward's standard calendar-based workflow.
Priority: Essential
Use Frequency: Often
Main Success Scenario:
  1. User signs in using Google.
  2. User selects a target date.
  3. User clicks Generate Checkin.
  4. Edward retrieves calendar events from Google Calendar.
  5. Edward generates and displays the daily checkin.
Alternative
Scenario Extensions:
  • If authentication fails, then the user is prompted to sign in again.
  • If no calendar events are found, then Edward informs the user that no activities were found for the selected date.
  • If the Google Calendar API is unavailable, then Edward displays an error message and the checkin is not generated.
Notes and Questions
  • Note: This workflow uses only Google Calendar as the data source.
  • Question: Should manually entered activities be supported in the Standard Edward workflow?

UC-02: Review Aggregated Workplace Activity

Summary: A TM8 user reviews the aggregated workplace activity collected from Google Calendar, Gmail, and Slack before generating a checkin.
Priority: Essential
Use Frequency: Often
Main Success Scenario:
  1. Open AI Assistance.
  2. Select Activity Log.
  3. Review the aggregated activity.
  4. Copy the activity log if needed.
Alternative
Scenario Extensions:
  • If activity cannot be retrieved, an error message is displayed.
  • If no activity exists for the selected date, an empty activity log is shown.
Notes and Questions
  • Displays a human-readable summary while preserving the raw activity for copying.
  • Should users be allowed to edit the activity before copying?

UC-03: Generate AI-Assisted Checkins Using Jacob

Summary: A TM8 user generates a daily checkin using Jacob after reviewing the aggregated workplace activity.
Priority: Essential
Use Frequency: Often
Main Success Scenario:
  1. Open AI Assistance.
  2. Launch Jacob.
  3. Paste the copied activity log.
  4. Review the generated checkin.
Alternative
Scenario Extensions:
  • If insufficient activity exists, Jacob requests additional information.
  • If the copied activity is invalid, Jacob asks the user to provide valid activity data.
Notes and Questions
  • Jacob generates grounded checkins only from supplied activity.
  • Should Edward automatically open Jacob after copying?

UC-04: Authenticate with Google Workspace

Main Success Scenario:

UC-06: Retrieve Activity for a Selected Date

Priority: Essential
