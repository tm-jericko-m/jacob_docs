Agreed Goals

The project aims to improve the current Edward app as Thinking Machines’ daily checkin generator. Edward currently helps TM8s generate checkins from Google Calendar data. The Jacob AI Assistant Checkin Generator aims to build on this by using AI to create more complete, grounded, and copy-pastable checkin drafts.

The goal is to reduce the effort needed for TM8s to submit daily checkins while improving the completeness and consistency of those checkins. The project will explore additional sources of work activity, such as Slack, Gmail, task notes, and user-provided context, so that checkins are not limited only to calendar events.

Stakeholders should agree that generated checkins remain drafts for user review, and that the system should avoid inventing work, inflating hours, or presenting uncertain activity as confirmed.

Environment

What is the system's business environment?
The system will be accessible through the Edward web application. Edward is a deployed web app that TM8s can visit through a URL. Its AI-assisted iteration, the Jacob AI Assistant Checkin Generator, will be introduced through the Edward user interface so users can choose between the standard Edward flow and the newer AI-assisted checkin flow.
When users choose Jacob, they will be routed to the Custom GPT or AI-assisted checkin experience. This experience will use uploaded prompt files and knowledge documents as its core instructions for generating daily checkins. The goal is to make checkin generation easier while keeping the user in control of reviewing and submitting the final output.
What is the system's physical environment?
The system is expected to behave similarly to the current Edward web application: a web-based tool that can eventually be made available to TM8s through a deployed domain. During development, the Jacob-related backend or API experiments may run locally and be exposed through tunneling for testing API calls through the Custom GPT Actions/OpenAPI setup.
This development setup will allow the team to test whether the Custom GPT can call backend endpoints that retrieve activity data from supported platforms. After testing, the expected path is to deploy the backend and web application properly for broader company use, similar to how Edward is already deployed.
What is the system's technology environment (hardware and software)?
The system will primarily run in a web environment. Users are expected to access it through standard modern browsers on their machines. The existing Edward application provides the starting point for the frontend experience.
The technology environment may include the current Edward codebase, a Custom GPT configuration, prompt and knowledge files, Google Calendar API integration, possible Slack/Gmail API exploration, an OpenAPI schema for Actions, and a backend service for retrieving structured activity data. During development, local servers and tunneling may be used before moving to a deployed backend.

Stakeholders / Actors

All
All stakeholders share the following key needs:
  1. AI-assisted checkin generation
  2. Up-to-date and accurate checkin drafts
  3. Easier retrieval of work activity data
  4. Less manual searching across Calendar, Slack, Gmail, or task tools
  5. Clear distinction between confirmed work and unclear work
TM8
TM8s are the primary users of the system. They need a faster and easier way to generate their daily checkins from the work they completed during the day. They benefit from being able to view or reconstruct their daily tasks without manually searching through multiple applications.

Key needs:

  1. Generate checkins with minimal effort
  2. Retrieve daily work activity from available sources
  3. Review and edit checkins before submission
  4. Avoid missed or backlogged checkins
  5. Produce checkins that are accurate, complete, and easy to paste into Slack
Operations / Admin Side
Operations and admin stakeholders need higher checkin submission rates so that TM8 work reporting is easier to monitor and maintain. They benefit when checkins are submitted consistently and when the process creates less friction for employees.

Key needs:

  1. Improved checkin submission rates
  2. Better visibility into completed daily work
  3. Reduced checkin backlog
  4. Consistent checkin format
  5. Confidence that generated checkins are grounded and not inflated
Managers / Reviewers
Managers or reviewers may use checkins to understand progress, accountability, and potential blockers. They need checkin outputs to be clear, accurate, and not misleading.

Key needs:

  1. Reliable checkin quality
  2. Concise summaries of completed work
  3. Visibility into missing or unclear work details
  4. Assurance that AI-generated checkins remain user-reviewed

User Stories

generate-checkin-after-long-day
A TM8 has had a long workday and wants to submit a checkin without manually reconstructing everything from memory. Calendar data alone does not fully capture all the work completed that day. The TM8 opens the AI-assisted checkin experience and uses a prompt such as "Generate my checkins today." The system returns a detailed, copy-pastable checkin draft based on available work activity data, which the TM8 reviews and pastes into Slack.
clarify-incomplete-checkin
A TM8 tries to generate a checkin for the day, but the available context from Calendar, Slack, Gmail, and other tools does not clearly add up to a complete workday. Instead of inventing missing hours, the AI assistant asks probing clarification questions. These questions help the TM8 remember additional tasks completed during the day. After the TM8 provides the missing context, the AI assistant generates a more complete and accurate checkin.
recover-checkin-backlog
A TM8 has missed several days of checkins and now has a one-week backlog. Instead of manually searching through Calendar, Slack, Gmail, and other workspaces for each day, the TM8 asks the AI assistant to generate checkins for the missed dates. The system collates available evidence across the relevant days and presents draft checkins for the TM8 to review. After making minor corrections, the TM8 approves the final versions and catches up on the backlog.

Performance and Capacity Needs

After a considerable period of use, the tool should help improve the checkin submission rate among TM8s. TM8s should spend less time generating their daily checkins, and the issue of checkin backlogs piling up should be reduced.

  • The system should support regular daily use by TM8s who need to generate checkins from available work activity data.
  • Generated outputs should remain fast enough to be useful in a daily workflow.
  • Generated outputs should be reliable enough that users do not need to heavily rewrite the results.
  • The quality of generated checkins should be evaluated through test cases and validator results.
  • An early benchmark is that generated checkins pass the validator at least 90% of the time across a defined set of test cases.
